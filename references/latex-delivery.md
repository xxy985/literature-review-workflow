# 多格式终稿与 LaTeX 排版交付

最终交付固定包含同一终稿的 Markdown（.md）、Word（.docx）、完整 LaTeX 工程，以及由该工程编译的 PDF。MD供阅读、修改与复用，DOCX供审阅、批注和常规文档交付，LaTeX供正式排版与投稿，PDF作为正式排版验收依据。四项缺一不可。

## 同一终稿与一致性

合入全部已接受修改并完成论断核验后，冻结一个终稿版本，记录内容基准及版本号，再据此生成三个格式。内部工作稿可保留 `[doi:...]` 审计标记；交付MD与DOCX须为清洁终稿，使用正常引文和完整参考文献，不能把内部工作稿或助理交接稿直接当作最终成果。

三个格式的正文、论断强度、数字、单位、公式、图表、图注及参考文献须一致；字体、分页和引用呈现样式可随格式调整，但引用指向必须通过DOI映射保持一致。任何实质修改都先回写终稿内容基准，再同步受影响格式并重新核对，禁止各版本独立漂移。

MD引用的图片等资源必须随包交付，使用可移植相对路径。DOCX可从清洁MD使用 to_docx.py 生成初版，但现有转换器不保证复杂公式、表格或学术排版保真；Agent必须实际检查并补齐，必要时用宿主可用的文档工具生成。不得因转换器能力不足而省略内容或只交付交接稿。

## LaTeX 构建

1. 门1记录课题领域；同时提前运行 `python <skill>/scripts/literature_review_env_check.py --delivery`。缺 TeX 环境不妨碍采集，但阻塞最终交付。TeX Live / MiKTeX 需提供 latexmk、XeLaTeX 及模板所需宏包；用 BibLaTeX 时还需要 biber。
2. 门3确认期刊模板、语言、参考文献样式。模板由用户提供；无模板时经认可使用通用模板，并注明未验证目标期刊适配。Agent 按模板编写 main.tex、参考文献数据库和图表，合入助理修改后再次核对论断。
3. 正文工作稿使用 `[doi:10.1234/example]`。参考文献数据库每条必须保留规范化 DOI；优先以 DOI 为引用键。模板不支持某些 DOI 字符时，仅将引用键编码，并在 `doi-map.tsv` 保留“编码键、DOI、成稿引用”一一映射，不引入另一个论文编号系统。
4. 把 main.tex、所有引用的 tex/bib/图表、必需的 cls/sty 和 doi-map.tsv 放在独立版本工程目录。使用相对路径，禁止依赖作者机器绝对路径。保留模板来源及许可信息。
5. 执行 `python <skill>/scripts/literature_review_latex.py <工程绝对路径> <新交付目录绝对路径>`。工具复制工程并用 latexmk + XeLaTeX 编译，保存日志；非零退出、缺 PDF、未解析引用均不能通过。失败后修正源工程，使用新的输出版本重试。
6. 实际逐页渲染 PDF，检查中文字体、公式、表格、图注、参考文献和溢出。逐项对照工作稿、DOI映射和参考文献。编译通过不等于学术或版式验收通过。

## 门4验收

在 artifacts/09-deliver/ 下建立同一版本交付目录，至少包含终稿.md及其资源、终稿.docx、完整可重编译LaTeX工程、该工程生成的PDF、构建日志、DOI映射、库导出、机械审计与论断核验报告。

逐项验收：MD及图片链接可打开；DOCX实际打开或渲染检查正文、公式和图表；LaTeX工程实际编译并逐页检查PDF；三个格式逐节核对内容与参考文献，保存一致性核对记录，注明版本、文件、检查结果及未解决项。没有完成实际检查的项目不得标记通过。

任一必需成果缺失、内容不同步、转换丢失信息，或缺编译器、宏包、字体、模板而无法完成验收时，记录阻塞及已有产物，不宣布完整交付。全部满足后停门4，请用户验收同一版本的整套成果。
