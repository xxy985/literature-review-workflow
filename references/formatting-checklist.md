# 格式轮检查表（C6 第三轮 + C8 定稿前必读）

> 用途：第三轮修改（格式维）与终稿交付前的逐项检查。`literature_review_check.py --diff / --cite-audit` 覆盖其中的自动化项；其余由 AI 逐项过、逐项打钩，不许"大致看过"。

## 一、自动化项（脚本管，AI 复核输出）

| 项 | 脚本/命令 | 通过标准 |
|---|---|---|
| 工作稿引用编号 | `check --cite-audit <含paper_id的工作稿> --strict` | 非零可识别编号、库内存在且已读；不证明语义支持 |
| 基础字符配对 | `to_docx` 转换前检查 | 弯引号和加粗标记计数配对；直引号提示需核对，确认合法时才用 --force |

成稿 DOI、数字编号连续性、悬空引文、占位注记及论断支持均由 Agent 按 claim-review.md 核对，cite-audit 没有这些自动能力。合法代码、标识符里的直引号不盲目替换。

## 二、引号与符号（中文学术文本高发雷区）

- [ ] 弯引号成对最近匹配：正文中 `"` 直引号须按成对原则转 `“”`，禁止逐字符盲目替换（会产生双左引号）
- [ ] 字面星号必须转义：正文里表字面含义的 `*`（如 `N*`）一律写 `\*`，防止 Markdown 把两个裸星号之间整段文字变斜体
- [ ] 化学式/编号撇号豁免：`4,4',4''` 这类撇号是合法记号，不作为引号问题处理
- [ ] 中文破折号、省略号风格统一（`——`/`……`，不混用半角）

## 三、docx 斜体回归（每次转 docx 后必做）

- [ ] Agent 检查导出文件是否出现非预期中文斜体；转换器不提供中文 italic 清单。发现异常回查源 Markdown 与渲染，修正后生成新版本
- [ ] 数据值加粗、变量斜体的样式是否按成文要求 Style sheet 统一

## 四、编号与对应

- [ ] 图表编号与正文引用一一对应（"如图3"必须存在图3）
- [ ] 图表标题完整、单位注明
- [ ] 术语首现给定义，全文同一术语同一写法（建同义词表核对）

## 五、引用与数据纪律

- [ ] 引用格式全篇统一（GB/T 7714 或成文要求拍板值）
- [ ] 数据表中的数值仅取 A 级（全文精读）来源；B 级（摘要级）文献的数据不得进数据表
- [ ] 库内 B 级文献被引用清单已向确认人报数（终稿正文不加任何 B 级标记——这条本身不许写进文章）
- [ ] 争议论点双方都有文献支撑，无单边断言

## 六、终稿收尾（C8 交付包）

- [ ] 版本历史文件齐全且未覆盖（v1→vN 独立文件，修改日志用 `check --diff` 生成）
- [ ] 每轮修改意见的逐条销项表已闭环（意见→处理结果→版本号）
- [ ] 交付目录：终稿 + 引用审计 + library.tsv 快照 + 人工核对清单（数据原文复核/DOI 终校/署名/查重预判四项留给确认人）
- [ ] 全文无"AI"自称痕迹（成文要求约定的口径）
